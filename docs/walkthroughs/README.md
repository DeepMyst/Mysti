# Practical walkthroughs

Follow a short path from a real task to a result you can inspect. These guides
apply to **Mysti 2.0.1 Beta 2** and include the current limitations beside the
steps that need them.

[Documentation home](../README.md) · [First-time setup](../GETTING-STARTED.md) · [Troubleshooting](../TROUBLESHOOTING.md)

| Your goal | Start here | What you will finish with |
| --- | --- | --- |
| Compare two approaches, then hand work to a reviewer | [Work with multiple agents](multi-agent-workflows.md) | Separately attributed opinions or an ordered design/review exchange |
| Create and refine a visual design | [Build a design in Canvas](canvas.md) | A saved design, a recoverable version and an HTML export |
| Inspect a running web app | [Take a visual look](visual-test.md) | A screenshot and observations you can investigate in chat |
| Explore an alternative or restore earlier code | [History, forks and checkpoints](history-and-checkpoints.md) | A separate conversation branch or an explicitly confirmed code rewind |

Start with [multiple agents](multi-agent-workflows.md) if you already have two
providers configured. Start with the [Canvas template path](canvas.md#create-your-first-page)
if you want to explore the visual editor without making a model request.

Every guide includes:

1. What you need before starting.
2. Numbered actions and the result to look for.
3. A screenshot and a short playable demonstration.
4. Recovery steps and links to the deeper reference.

Screenshots and recordings use **labelled sample data** in the shipped
interface. They explain the controls; provider acceptance and production
limits are recorded separately in [production readiness](../PRODUCTION_READINESS.md).
Each guide ends with implementation and regression references so a maintainer
or coding agent can check the instructions against the source.
