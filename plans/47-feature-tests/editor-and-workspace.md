# Editor and workspace feature test plan

Status: **proposed; not executed**. This inventory was grounded in the current manifest and implementation on 2026-10-09. Existing test links describe available coverage, not fresh results or proof of sustained native-editor behavior. Only this plan is changed by this work.

Use the fixtures, evidence policy, provider matrix, and release gates in the [comprehensive plan](../47-comprehensive-feature-test-plan.md). Conversational profiles are **S: 45–60 minutes / 25 turns**, **W: 8 hours / 250 turns**, **E: 24 hours / 750 turns**, and **P: 5 days / 1,000 turns with nightly editor restart**. Fixture references: F1 small Node retry service with executable tests; F2 full-stack application, 30–100k LOC; F3 monorepo, 10k files / 500k LOC; F4 adversarial filenames/content and synthetic secrets; F6 isolated service accounts and two peers. For standalone features without chat turns, the catalog-specific meaningful operation counts below may satisfy the feature workload while retaining the actual elapsed profile and restart requirements. Integrated developer journeys retain the main plan's chat-turn totals, with these feature operations distributed through them. Accelerated-clock boundary tests supplement actual elapsed-time runs; they cannot certify an 8-hour, 24-hour, or five-day soak.

Priority: **P0** prevents authority escalation, unintended disclosure, destructive writes, or cross-workspace contamination; **P1** establishes core daily usefulness and recovery; **P2** establishes polish and secondary integrations. All failures remain recorded, including P2. Unless a feature says otherwise, collect a native-editor trace, panel/conversation/workspace identifiers, redacted transport/event evidence, before/after filesystem or state snapshots, and resource samples under its EW ID. Capture selected VS Code tab identity explicitly; an inner iframe reporting visibility does not establish that its containing editor is active. Use distinct per-panel canaries and temporary accounts/repos, never production credentials in captured fixtures.

Ordinary conversation/composer behavior, provider setup/authentication, collaboration execution, memory lifecycle, plugins/connections, autonomous execution, visual testing, and Desk have owners in the comprehensive plan. This document covers their editor entry routes only where needed. **Canvas is excluded.** A slash-menu enumeration may encounter its entry; do not execute it or count it as tested here. No feature is considered covered merely because a menu item exists, a mock returns successfully, or an LLM says it read the expected file.

## EW-01 — Add files, editor selections, and folders to context

- **Priority / surface / source:** P1. Explorer/editor “Add to Context,” context chips, attach dialog, context show/clear actions; [`ContextManager`](../../src/managers/ContextManager.ts), [command registration](../../src/extension.ts), [panel handlers](../../src/providers/ChatViewProvider.ts), [manifest](../../package.json). Folder enumeration currently includes at most 20 files and skips a fixed set of common generated directories; it is not evidence of complete `.gitignore` enforcement.
- **Real use:** In F1, select only the retry backoff function; add its tests through Explorer; add a folder with 19 files, then variants with 20 and 21. Ask “Explain the retry contract using only the enabled context, then identify the missing timeout test.” Toggle one item off, remove another, clear, and re-add. Repeat from editor selection, editor context menu, Explorer file/folder, and an empty-editor window. Include multiline Unicode selections and zero-length selections.
- **Sustained load:** S performs 40 add/toggle/remove actions. W performs 200 actions while moving between F2 and F3, including ten folder adds. P restores and revalidates five representative selections daily.
- **Fault injection:** Delete or deny read permission to a selected file before add; supply a binary file, symlink, recursive directory link, excluded directory, duplicate path with case/normalization differences, and F4 filenames containing spaces, `#`, quotes, and non-ASCII text.
- **Pass/fail / evidence:** Chip type, label, line range, enabled state, and captured outbound context agree byte-for-byte with the selected fixture. Disabled/removed items never enter subsequent prompts. Folder limits are bounded and understandable; no silent claim that all files were included. Errors are actionable and do not corrupt the remaining list. Save source hashes and the exact selected-range boundaries.
- **Existing → proposed:** [Context unit coverage](../../tests/managers/contextManager.test.ts) exists. Add native Explorer/editor entry-route checks and an explicit ignored-files/limit contract case; a unit read succeeding is insufficient evidence of correct active-panel routing.

## EW-02 — Context isolation, refresh, persistence, and cleanup

- **Priority / surface / source:** P0. Persistent stable panel IDs and transient tab IDs have different lifetimes: saved file context is reread, selection context is a snapshot, and orphaned transient keys are swept.
- **Real use:** Open sidebar A and editor tabs B/C in F2, each with distinct context canaries. Alternate additions through each supported UI route, including contributed global commands. Edit an included file on disk, preserve a selected snapshot, send from each panel, reload the window, and reopen the workspace. Repeat with another workspace containing identically named files. - **Fault injection:** Reject memento writes, interrupt shutdown during persistence, rename/delete files, revoke permission after save, corrupt one persisted record, and restore stale transient IDs. Race clear against refresh and selection add against tab disposal.
- **Pass/fail / evidence:** No panel/workspace receives another's canary. Current files refresh while saved selections retain their intended snapshot; missing files disappear without destroying unrelated context. Failed persistence is reported without an unhandled rejection. Temporary-tab cleanup is bounded; do not falsely demand persistence the implementation does not promise. Record keys, sizes, ownership, and restore decisions.
- **Existing → proposed:** [Rejected writes](../../tests/managers/contextManagerPersistRejection.test.ts), [persisted keys](../../tests/managers/contextManagerPersistedKeys.test.ts), and [context manager](../../tests/managers/contextManager.test.ts).
